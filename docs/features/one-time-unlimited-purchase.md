# Feature — 일회성 무제한 촬영 구매

작성일: 2026-09-27
상태: Billing 연결·기존 구매 확인·상품 가격 조회 및 설정 화면 표시 구현 중 (결제창·촬영 권한 연결 미구현)
관련 요구사항: [제품 요구사항 §4](../00-product-requirements.md#4-p1-이후)
관련 단계: [Roadmap Step 20](../06-implementation-roadmap.md#step-20--일회성-무제한-구매-별도-feature-아직-구현하지-않음)

이 문서는 새 Feature에서 바로 작업을 이어가기 위한 인계 문서다. 대화에서 제시했던 연결 예제는 구현 완료 증거가 아니며, 실제 저장소의 코드와 빌드 결과를 다시 확인한다. 현재 Step 19의 미완료 검증도 별도로 남아 있다.

## 1. 확정된 제품 정책

- 공식 배포판은 무료 촬영 24회를 제공한다. Warm/Dusk 등 필름 프리셋과 무관하게 한도를 공유한다.
- 한 번 구매하면 촬영 횟수 제한을 해제한다. 구독, 추가 장수 판매, 소모성 상품은 구현하지 않는다.
- 무료 사용 횟수는 로컬 저장만 사용한다. 무료 사용량 보호를 위한 로그인·서버 카운터·기기 식별은 필요하지 않다.
- 앱 데이터 삭제·재설치로 무료 횟수가 초기화돼도 괜찮다. 그렇다고 재설치 시 반드시 초기화되도록 만드는 것은 아니다.
- 기존 백업을 유지한다. `allowBackup`을 끄거나 무료 카운터를 백업에서 제외하는 변경은 하지 않는다.
- 유료 촬영은 무료 횟수를 추가 차감하지 않는다. 기존 무료 사용 횟수도 구매 시 초기화하지 않는다.
- 소스를 GitHub에 공개하고 직접 빌드하거나 제한을 수정해 사용하는 것을 막지 않는다. 무료 제한의 우회 방지가 이 Feature의 성공 기준은 아니다.
- 구매 처리는 서버 없는 Google Play Billing 클라이언트 구현을 선택한다. 정상 구매자의 결제 완료·복구·실패 처리는 제대로 구현한다.

근거: 사용자 합의와 `00` §4. **(Product Requirement)**

## 2. 이번 Feature에서 하지 않는 것

- 회원가입/로그인, 계정별 무료 횟수, 서버 기반 검증·사용량 원장, 기기 식별, 강한 위변조 방지.
- 구독 갱신, 소모성 촬영권, 추가 필름 판매, 별도 결제 제공자.
- Room 도입, CameraX bind/GL draw/SurfaceProvider/회전 정책 재설계.
- 소스 공개를 이유로 모든 빌드의 결제 우회를 막는 작업.
- 백업 끄기 또는 재설치 초기화 보장.

이 선택은 서버 검증과 같은 보안을 확보했다는 뜻이 아니다. Google이 권장하는 서버 구매 검증과는 구분한다. 서버 자격증명이나 Developer API 비밀 키를 클라이언트에 넣어 서버 검증을 흉내 내지 않는다. [공식 보안 지침](https://developer.android.com/google/play/billing/security) **(Implementation Decision / API Guidance)**

## 3. 현재 저장소 기준 출발점

| `ui/camera/CameraScreen.kt` | 무료 횟수만 보고 셔터 비활성화·`00/24` 표시 | 유료 권한을 함께 반영하고 무제한 표시를 제공한다 |

| `ui/settings/SettingsScreen.kt` | 시작 필름·격자 옵션만 표시 | 무제한 촬영 상태·가격·구매·구매 확인/재시도 진입점을 추가한다 |
| `MainActivity.kt` | 볼륨 입력·Navigation 진입점 | 결제 UI에 필요한 Activity와 앱 전경 복귀 연결점을 검토한다 |

중요: 촬영 전 24회 검사만 우회하면 충분하지 않다. 현재 저장 후의 `recordSavedPhoto()`도 24에서 예외를 던지므로, 유료 촬영은 이 호출을 건너뛰어야 한다. 유효한 유료 권한이 있으면 무료 카운터의 읽기·쓰기 오류로 촬영을 막지 않는다. 카메라 권한·중복 촬영·카메라 준비 상태 등 기존 검사는 유지한다. **(Current Code / Implementation Constraint)**

## 4. 상태를 구분하는 원칙

연결 상태, 구매 권한, 무료 사용 횟수를 하나의 Boolean으로 합치지 않는다.

| 상태 | 뜻 | 촬영 판단 |
|---|---|---|
| Billing 연결 준비 완료 | 서비스와 통신 가능 | 이것만으로 유료 권한을 주지 않는다 |
| 구매 조회 중/오류 | 소유 여부를 아직 확인하지 못함 | 미구매로 확정하지 않는다. 확인된 무료 잔여 횟수는 사용할 수 있다 |
| 미구매 확인 | 해당 무제한 상품의 구매 권한이 없음 | 무료 횟수가 남았으면 허용, 소진됐으면 구매 안내 |
| 결제 대기 | 아직 구매 완료가 아님 | 새 유료 권한은 부여하지 않는다. 무료 잔여 횟수 사용은 별개다 |
| 구매 완료 확인 | 대상 상품의 유효한 구매를 클라이언트에서 확인 | 무제한 허용, 무료 횟수 기록 생략. 승인 실패 재시도와 부여 시점은 §7에서 확정한다 |

결제창에서 즉시 취소하는 경우와 `PENDING` 거래가 나중에 거절·만료로 취소되는 경우를 구분한다. 앱 실행/복귀 후 성공한 구매 재조회에서 기존 대기 거래가 더 이상 확인되지 않으면 그 거래의 대기 상태와 표시를 해제한다. 대상 상품의 다른 `PURCHASED`/`PENDING` 거래도 없고 상품을 구매할 수 있는 상태이면 구매 버튼을 다시 활성화한다. 조회 오류나 로컬 대기 시간 경과만으로 취소를 확정하지 않는다. **(Implementation Decision)**

설정 화면의 '무제한 촬영' 영역을 구매 진입점으로 사용한다. 무료 한도 소진 안내는 이 영역으로 이동시킨다. 설정 화면은 구매 확인 중·미구매·결제 대기·무제한 이용 중·조회 실패를 구분하고, 조회 실패에는 재시도 동작을 제공한다. '구매 확인/복원'은 새 유료 상태를 수동으로 켜는 스위치가 아니라 Google Play의 현재 소유 내역을 다시 조회하는 동작이다. 상품 가격은 Play의 상품 조회 결과를 사용하며 소유 여부나 상품 정보가 확인되지 않았을 때 구매 버튼을 임의로 활성화하지 않는다. 앱 시작/복귀의 일시적인 조회 오류는 카메라 위에 반복 Dialog를 띄우지 않고, 무료 촬영이 가능한 상태는 유지한다. **(Product UX / Implementation Decision)**

셔터 진입 시 유료/무료 중 어떤 근거로 촬영을 허용했는지 한 번 정하고, 그 촬영의 저장 후 횟수 처리에 같은 판단을 사용하는 방향을 검토한다. 촬영 도중 구매 상태 변경으로 무료 차감 여부가 흔들리지 않는지 테스트한다. **(Implementation Proposal)**

## 5. Google Play 계약과 구현 주의점

- 상품은 `INAPP` 비소모성 일회성 상품으로 구성하고 소비(`consume`)하지 않는다.
- 대상 상품 ID와 `PURCHASED`를 확인한다. `PENDING`, 결제창 실행 성공, 서비스 연결 성공만으로 해제하지 않는다.
- 새 구매 콜백과 앱 전경 복귀 시 구매 조회를 같은 처리 경로로 합친다. 조회 오류를 빈 구매 목록으로 처리하지 않는다.
- 이미 승인된 구매와 미승인 구매를 구분하고 미승인 완료 구매는 승인(`acknowledge`)한다. `PURCHASED` 전환 후 3일 이내에 승인하지 않으면 Google Play가 자동 환불하고 구매 권한을 회수한다. `PENDING` 동안에는 승인하지 않으며, 승인 기한은 앱이 구매를 발견한 시점이 아니라 `PURCHASED`로 전환된 시점부터 시작한다. 승인 실패는 재시도·재조회하며 유효한 기존 구매가 있는 사용자에게 재구매를 요구하지 않는다.
- 구매 콜백이 중복돼도 권한·알림·승인 처리가 중복되지 않아야 한다.
- 현재 구현 중인 `BillingRepository`에는 `@ActivityRetainedScoped`가 적용되어 있고 `MainActivity`가 구성 변경 때 Client를 닫지 않도록 되어 있다. 단일 Activity의 전경 복귀 신호를 `MainActivity`가 Repository에 전달하고, 연결·조회·구매 상태는 Repository가 담당한다. `MainActivity`, `CameraViewModel`, `SettingsViewModel`이 같은 인스턴스를 공유하도록 유지한다. 최종 종료 때만 `endConnection()`으로 정리하고 종료된 Client는 재사용하지 않는다. Repository에는 Application Context만 주입하고 Activity를 장기 보관하지 않으며, 설정 화면에서 결제창을 열 때만 현재 Activity를 전달한다. 회전·설정 왕복·Home 복귀에서 인스턴스 공유와 연결·정리를 검증한다. **(Current Code / Hilt API Contract / Implementation Plan)**
- 앱 실행/복귀 때 소유 내역을 갱신한다. 서버 없는 구현은 앱이 꺼져 있거나 오프라인일 때 환불을 즉시 감지한다고 보장할 수 없다.

근거: [공식 연동 지침](https://developer.android.com/google/play/billing/integrate). **(Google Play Billing API Contract)**

서버 없는 구현은 승인 전에 앱이 종료되거나 통신이 끊기고 기한 내 복구되지 않으면 승인 재시도를 보장할 수 없다. 앱이 꺼진 동안 대기 결제가 완료된 경우에도 앱의 다음 실행까지 승인 처리가 지연될 수 있다. 따라서 자동 환불 가능성을 한계로 명시하고, 앱 실행/복귀 시 미승인 구매를 재조회해 처리한다. 기한 초과 여부를 로컬 시간만으로 판단해 권한을 지우지 않는다. 성공한 재조회에서 대상 상품의 유효한 구매가 없음을 확인하면 기존 유료 권한·승인 대기 상태와 캐시를 갱신하고, 남은 무료 횟수에 따라 촬영을 허용한다. 조회 실패 시에는 §7에서 확정할 오프라인 정책을 따른다. [공식 보안 지침의 클라이언트 승인 한계](https://developer.android.com/google/play/billing/security) **(API Guidance / Implementation Decision)**

구매 승인, 구매 유효성 확인, 캐시 갱신은 서로 다른 작업이다. 로컬 `isPaid=true`를 저장했다는 이유만으로 영구적인 구매 검증이 끝났다고 취급하지 않는다. 공개 소스에 포함할 검증 방식의 한계도 명시한다.

백업 복원으로 무료 횟수가 재설치 때 돌아올 수 있다는 사실은 허용된 제품 동작이다. [Android 백업·복원 지침](https://developer.android.com/identity/data/autobackup) **(Android API Contract / Product Requirement)**

## 6. 구현 순서 — 하나의 Feature 안에서 진행

1. **외부 설정 확인**: Play Console 앱/상품/구매 옵션/가격/테스터를 준비하고 확정된 상품 ID를 기록한다. 서버 설정은 만들지 않는다.
2. **의존성·연결**: 최신 안정 버전을 실제 배포 목록에서 확인하고 Gradle Sync/빌드·서비스 연결을 검증한다. 이전 안내에서 확인한 버전은 `9.1.0`이지만 새 Feature 시작 시 다시 확인한다. 아직 구매 UI를 노출하지 않는다.
3. **조회·상태**: 상품 정보와 기존 구매를 조회하고 연결/권한/대기/오류를 분리한다. 가격은 조회 결과를 표시하고 코드에 고정하지 않는다.
4. **구매 처리·복구**: 대상 상품/구매 상태/선택한 클라이언트 검증을 확인하고 승인·재시도·복구를 구현한다. `ITEM_ALREADY_OWNED`는 기존 구매 조회로 연결한다.
5. **구매 UI**: 설정 화면에 무제한 촬영 영역을 추가하고 무료 한도 안내에서 그곳으로 이동한다. 사용자가 명시적으로 구매 버튼을 눌렀을 때만 결제창을 연다. 구매 확인/복원 및 조회 실패 재시도를 제공한다. 취소·실패·대기는 안내하고, 결제창 결과만으로 기존 구매 권한을 지우지 않는다. 대기 거래의 취소 후 상태 해제와 구매 버튼 복구는 §4의 재조회 결과를 따른다. 볼륨 키 입력만으로 결제창을 직접 열지 않는다.
6. **촬영 권한 연결**: ViewModel과 셔터 UI를 같은 권한 상태에 연결한다. 유료 촬영은 무료 카운터 기록을 생략하고, 무료 저장 성공은 기존 기록 방식을 유지한다.
7. **완료 검증**: §8의 결제·카메라 회귀를 통과한 뒤 기능 단위로 커밋한다. 연결 예제나 TODO만으로 Feature 완료를 선언하지 않는다.

`BillingRepository` 같은 구체 클래스는 해당 단계에서 추가한다. 범용 결제 전략, 다른 스토어용 추상화, 미사용 모듈을 미리 만들지 않는다. Application/Activity lifecycle, CameraViewModel과 구매 UI 간 공유 범위를 현재 코드로 검토하되 CameraX/GL 소유권을 옮기지 않는다. **(Implementation Plan)**

Play Console 설정과 테스트 구매 준비는 코드와 별도의 작업이다. GitHub의 임의 빌드가 공식 배포판과 동일하게 결제 가능한 환경이라고 가정하지 않는다. [설정 준비 안내](https://developer.android.com/google/play/billing/getting-ready), [공식 테스트 지침](https://developer.android.com/google/play/billing/test)

## 7. 구현 전 확정할 항목

- 실제 상품 ID, 판매 가격/지역, 구매 옵션, Play Console와 테스트 계정 준비 상태.
- 구매 UI는 설정 화면의 무제한 촬영 영역에 둔다. 무료 소진 안내에서 이 영역으로 이동하는 구체적인 문구·탐색 방식과 무제한 표시(`∞` 또는 `UNLIMITED`)는 아직 확정하지 않았다.
- 오프라인에서 이전 확인 권한을 어떻게 캐시·유효기간 관리할지, 첫 설치에서 조회 실패 시 어떤 안내를 할지.
- 승인 실패 시 권한을 언제 부여할지, 재시도 시점과 승인 대기 UI. §5의 승인 기한·자동 환불 조건은 확정된 API 계약이며 이 결정으로 바꿀 수 없다. 미승인 완료 구매를 결제 실패나 미구매로 단순 치환하지 않는다.
- 클라이언트 구매 검증 범위와 로컬 캐시 저장 여부. 서버가 없다는 이유로 유효성 확인 자체를 했다고 단정하지 않는다.
- 환불/권한 회수 재조회 후의 안내와 촬영 중 상태 변화 처리. 유료 기간에 무료 횟수를 차감하지 않으므로 기존 무료 잔여 횟수는 유지된다.
- 직접 빌드 사용에 대한 README 안내와 공개 라이선스.

이 목록은 **Verify First / Pending Product Decision**이다. 새로운 Feature에서 질문·구현·검증으로 해소하고 임의의 정책을 코드 기본값으로 숨기지 않는다.

## 8. 완료 검증 목록

- [ ] 연결 성공을 구매 완료로 처리하지 않음. Play 서비스가 없는 환경에서도 Preview·무료 촬영이 불필요하게 깨지지 않음.
- [ ] 무료 `23/24`에서 저장 성공 후 `24/24`, 이후 두 셔터 차단. 실패 촬영은 증가하지 않음.
- [ ] 무료 소진 후 구매 성공 시 두 셔터 촬영 허용. 여러 장 저장해도 무료 카운터를 추가 차감하지 않음.
- [ ] 유료 권한 확인 시 무료 카운터 로딩 오류·저장소의 24회 예외가 촬영을 막지 않음.
- [ ] 구매 취소·실패·대기는 새 무제한 권한을 부여하지 않음. 지연 승인 테스트 결제로 `PENDING` → `PURCHASED` 전환을 앱 복귀 후 발견하고, 구매 검증·권한 부여·승인 처리로 이어짐.
- [ ] 지연 거절 테스트 결제로 대기 거래가 취소된 뒤 앱 복귀/재시작·성공한 재조회를 거치면 대기 표시가 해제됨. 다른 유효한 구매나 대기 거래가 없을 때 다시 구매할 수 있고, 새 구매 성공 후 무제한 촬영이 가능함. 조회 실패만으로 대기 거래를 취소 처리하지 않음.
- [ ] 미승인 구매 승인 성공·실패 후 재시도, 중복 콜백, 이미 소유한 상품 처리 검증. `PENDING`에는 승인 요청을 보내지 않고, 정상 처리와 일시 오류 복구 시 `PURCHASED` 전환 후 승인 기한 내 완료를 확인함.
- [ ] license tester 환경에서 승인 요청을 의도적으로 생략해 자동 환불을 확인함. 앱 종료·재실행 후 성공한 구매 재조회에서 회수된 권한·승인 대기 상태·캐시가 정리되고, 기존 무료 횟수는 보존됨. 무료 잔여 횟수가 있으면 촬영 가능하고 `24/24`이면 두 셔터가 차단됨. 기한 경과 후 조회 실패만으로 권한을 회수하지 않음.
- [ ] 구매 중 프로세스 종료/통신 끊김 후 복구. 공식 앱의 동일 Play 계정에서 재설치·다른 기기 구매 복구 검증.
- [ ] 권한 조회 실패를 미구매로 취급하거나 확인된 구매를 근거 없이 덮어쓰지 않음. 확정한 오프라인 정책 검증.
- [ ] 테스트 환불/권한 회수 후 성공한 구매 재조회와 촬영 정책 반영. 즉시 서버 동기화와 혼동하지 않음.
- [ ] 백업 설정 유지. 무료 횟수가 초기화되거나 복원되는 경우 모두 허용된 정책으로 처리함.
- [ ] Camera↔Settings/구매 UI 이동, 회전·큰 화면·볼륨 입력·Home 복귀·저장 필터/방향 회귀 통과.
- [ ] 설정 화면에서 미구매·조회 중·조회 실패·결제 대기·무제한 이용 중 표시와 구매/구매 확인/재시도 동작 검증. 조회 오류 때 구매 버튼을 활성화하거나 기존 구매자를 미구매로 단정하지 않음.
- [ ] 실결제 출시 전 license tester 환경에서 시험. 서명 키·서비스 계정·비밀 자격증명·구매 토큰을 저장소/공유 로그에 노출하지 않음.

지연 승인·거절은 각각 `Slow test card, approves after a few minutes`와 `Slow test card, declines after a few minutes`로 검증한다. license tester의 일회성 구매는 미승인 상태가 약 3분 지속되면 자동 환불되므로 실제 구매의 3일 승인 기한과 구분한다. [공식 일회성 구매·대기 결제 테스트 지침](https://developer.android.com/google/play/billing/test#test-pending-purchases) **(Google Play Billing Test Guidance)**

실제 통과 결과는 환경·날짜·관측 내용을 추가한다. 현재는 결제 테스트를 수행하지 않았으며 체크 항목은 완료 표시가 아니다.

## 9. 별도 Feature 시작 시 인계

- 권장 기능 커밋: `feat: add one-time unlimited capture purchase`.
- 브랜치 이름 예시: `codex/one-time-unlimited-purchase`. 사용자에게 다른 이름 지정이 있으면 따른다.
- 현재 작업 트리에 기존 카메라/설정/무료 횟수 변경이 여러 개 남아 있으므로 시작 기준 커밋과 포함할 변경을 먼저 확인한다. 이 문서 작성에서 커밋·브랜치 생성은 하지 않았다.
- 먼저 `CLAUDE.md`, `docs/00` §4, `docs/06` Step 19~20, 이 문서를 읽는다. Step 19의 남은 테스트를 지우거나 자동으로 완료 처리하지 않는다.
- 사용자 요청이 코드 안내이면 단계별 예제와 설명을 제공하고, 직접 파일 변경은 명시적 지시가 있을 때 수행한다.
- 매 단계에서 코드 흐름과 실패 경로를 설명한다. 서비스 연결만 구현한 코드에는 구매 UI를 열지 않는다.
