# 필카메라 에뮬레이터 테스트 체크리스트

이 문서는 NewFeelCamera의 기본 동작을 에뮬레이터에서 한 번에 점검할 때 사용하는 검사 목록이다. 한 번의 실행에서 가능한 항목을 모두 확인하되, 근거를 확보하지 못한 항목은 **미검증**으로 남긴다. 검사 절차를 실행하는 프로젝트 스킬은 [필카메라 에뮬레이터 테스트](../.agents/skills/newfeel-emulator-check/SKILL.md)다.

## 적용 범위와 준비

- 현재 앱의 대상은 **후면 카메라**, **WARM/DUSK 필름**, 화면·볼륨 셔터, 시작 필름·격자 설정, 촬영 횟수 제한 없는 무료 사용이다. 줌·플래시·앱 내 갤러리 버튼도 현재 코드에 연결돼 있으며, 추가 검사 기준은 [실기기 체크리스트의 P15~P17](physical-device-test-checklist.md)을 참고한다. 플래시 실제 발광은 실기기에서 확인한다.
- 실행 전에 검사할 Git 상태, APK 빌드, 에뮬레이터 이름/API 수준, 기존 사진 수를 기록한다. 빌드·단위 테스트·기기 테스트 결과는 실제 화면 점검 결과와 구분한다.
- 색과 방향 비교에는 **색 구분이 되고 좌우·상하가 비대칭인 장면**을 사용한다. 고정된 화면만 보이면 프리뷰가 계속 갱신되는지 따로 확인한다.
- 촬영 사진은 `Pictures/FeelCamera`에서 새 파일을 찾아 실제로 열어 본다. 프리뷰 스크린샷과 JPEG를 같은 촬영 건으로 연결한다.
- 권한 초기화·의도적인 오류 재현은 별도 테스트용 에뮬레이터나 복원 가능한 상태에서 진행한다. 기존 사용 사진과 앱 데이터는 지우지 않는다.

## 점검 항목

| ID | 검사 | 통과 기준 |
| --- | --- | --- |
| **P01** | 첫 실행과 카메라 권한 | 콜드 스타트가 성공한다. 테스트용 에뮬레이터에서 권한 허용·거부·재허용 시 크래시가 없고, 허용 후 프리뷰가 표시된다. |
| **P02** | 후면 카메라 프리뷰 | 장면 변화가 연속 반영된다. 검은 화면, 멈춤, 의도하지 않은 좌우·상하 반전, 눈에 띄는 비율 왜곡이 없다. |
| **P03** | 필름 선택과 실시간 적용 | 같은 장면에서 WARM → DUSK → WARM으로 전환할 때 선택 표시와 프리뷰가 함께 바뀐다. 기준 색상표가 있다면 기대 LUT 색과도 비교한다. 단순히 두 화면이 다르다는 사실만으로 LUT 정확성을 통과 처리하지 않는다. |
| **P04** | 필름 × 방향 촬영 | WARM/DUSK 각각 0°·90°·180°·270°에서 촬영한다. 각 JPEG에 셔터 시점 필름이 적용되고, 프리뷰와 색감·구도가 대체로 일치한다. 노출·JPEG 압축으로 생기는 작은 차이는 허용한다. |
| **P05** | 저장 사진의 회전 | P04의 JPEG마다 이미지 내용, 디코딩된 가로·세로 크기, EXIF 방향 정보가 있다면 그 값도 확인한다. 비대칭 기준물이 바르게 보이고, 좌우 반전이나 이중 회전이 없다. EXIF만으로 판정하지 않는다. |
| **P06** | 방향별 화면 배치 | 물리적 기기 방향을 바꿨을 때 폰의 프리뷰 영역과 버튼 레일은 설계된 위치를 유지하고, 글자·아이콘은 읽기 좋은 방향을 향한다. 에뮬레이터 창 회전만 가능했다면 물리 방향 검사는 미검증으로 기록한다. |
| **P07** | 촬영 결과와 저장 안내 | 성공한 셔터 한 번당 열리는 JPEG가 정확히 한 장 생기고, 저장 완료 안내가 나타난다. 격자·버튼·안내 문구는 JPEG에 포함되지 않는다. |
| **P08** | 화면·볼륨 셔터 | 화면 버튼, 볼륨 ↑/↓, 빠른 연타, 길게 누르기를 검사한다. 의도한 입력 한 번에 사진 한 장만 저장되고 촬영 중 상태에 갇히지 않는다. 설정 화면에서는 볼륨 키가 시스템 음량을 조절한다. |
| **P09** | 셔터 시점의 필름 고정 | 필름 A로 셔터를 누른 직후 처리 중 필름 B로 바꿔도 저장 사진에는 A가 적용된다. 처리 시간이 너무 짧아 상황을 만들 수 없으면 이 항목은 미검증이다. |
| **P10** | 설정 저장 | 시작 필름과 격자 설정을 바꾸고 화면을 왕복하거나 앱 프로세스를 재시작해도 값이 유지된다. 카메라 화면에서 임시로 필름을 바꿔도 저장된 시작 필름은 변하지 않는다. |
| **P11** | 화면 이탈과 복귀 | 설정 왕복, 홈 이동·복귀, 화면 꺼짐·켜짐, 프로세스 종료·재실행 후 움직이는 프리뷰와 촬영이 복구된다. 검은 화면·오래된 프레임·크래시가 없다. |
| **P12** | 촬영 제한 해제 | 이전 버전에서 무료 촬영 24장을 모두 사용한 앱 데이터가 있는 테스트 환경에서도 화면·볼륨 셔터로 새 사진을 저장할 수 있고, 촬영 횟수·구매 안내가 표시되지 않는다. 기존 데이터가 없다면 한도 도달 이력 검사는 미검증으로 기록한다. |
| **P13** | 촬영 실패와 복구 | 안전하게 반복 가능한 실패 조건이 있을 때 오류 안내가 나오고, 공개된 사진 수가 늘지 않으며, 조건 복구 후 다시 촬영된다. 실패 조건을 만들 수 없다면 미검증이다. |
| **P14** | 화면 크기 변경 | 사용 가능한 작은 화면·큰 화면·분할 화면에서 텍스트나 버튼이 겹치거나 잘리지 않고, 크기 변경 뒤 프리뷰와 촬영이 동작한다. 준비되지 않은 기기 종류는 따로 미검증으로 기록한다. |

P04와 P05는 아래 **8개 조합을 각각** 기록한다. 센서의 물리 방향을 조절할 수 없다면 창 회전 결과를 대신 통과로 기입하지 않는다.

## 결과 기록 기준

각 ID에 `통과 / 실패 / 미검증`, 실제 관찰, 근거 파일, 실패 재현 절차를 남긴다. 결과물은 `build/reports/newfeel-emulator-check/<실행 ID>/`에 저장한다. 필름 비교에는 해당 프리뷰 스크린샷과 JPEG를 함께 남기고, 회전 판정에는 JPEG의 실제 내용과 크기·메타데이터를 함께 사용한다. 이 앱은 회전을 사진 픽셀에 반영하므로 EXIF 방향 값이 없거나 기본값인 것만으로 실패가 아니다.

기본 실행에서는 P01~P11을 우선 점검한다. P12~P14도 같은 실행에서 가능한 만큼 진행하되, 별도 에뮬레이터나 재현 조건이 없으면 이유를 적고 미검증으로 남긴다. 에뮬레이터 결과만으로 실기기의 센서 방향, 카메라 색 재현, 기기별 GPU 동작을 최종 판정하지 않는다.
