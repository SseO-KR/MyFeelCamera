## 검증 기준

필름 카메라는 앱이 켜지는 것만으로 검증이 끝나지 않습니다. 프리뷰에서 보인 선택이 JPEG에 반영되는지, 방향이 맞는지, 화면에서 돌아온 뒤 새 프레임과 촬영을 처리하는지까지 확인해야 합니다.

| 확인 대상 | 근거 | 이 근거만으로 판단하지 않는 것 |
| --- | --- | --- |
| 빌드·정적 검사 | Debug/Release 빌드, Lint, Manifest | 실제 첫 실행·촬영 성공 |
| 순수 상태 로직 | 권한 복구·촬영 허용 조건 등의 단위 테스트 | 시스템 권한 대화상자의 실제 동작 |
| GL·Surface | 실제 EGL/OES/SurfaceRequest를 사용하는 기기 테스트 | 모든 제조사·GPU의 자원 안정성 |
| 촬영 결과 | 촬영 직전 화면과 새 JPEG의 연결, 내용·크기 확인 | 기준 색상표 없는 절대 색 정확도 |
| 복귀·레이아웃 | 화면과 로그, 복귀 뒤 촬영 | 고정 그림만으로 움직이는 프리뷰 재개 |

근거를 확보하지 못한 항목은 미검증으로 남깁니다. EXIF 값만으로 사진 방향을 판정하지 않고 실제 픽셀 내용과 가로·세로 크기도 확인합니다. 검사 기준: [실기기](../physical-device-test-checklist.md) · [에뮬레이터](../emulator-test-checklist.md)

## 실기기 검증 완료

**개발자가 직접 실기기 검증을 완료했으며, 2026-10-08에 완료 사실을 확인했습니다.** 근거는 개발자의 직접 확인입니다. AI의 새 기기 테스트 실행 결과로 기록하지 않습니다. **(사용자 확인)**

| 기록 항목 | 확인한 내용 |
| --- | --- |
| 수행자 | 개발자 본인 |
| 상태 | 실기기 검증 완료 |
| 완료 확인일 | 2026-10-08 · 실제 검사 일자는 별도 기록 필요 |
| 기기 모델·Android 버전·검사 앱 버전 | 세부 환경은 아직 기록하지 않음 |
| 개별 시나리오와 결과 | 완료 사실을 확인했으며, 항목별 판정은 별도 기록 필요 |

실기기 검증 완료와 각 체크리스트 항목의 통과 판정은 구분합니다. 기기 정보나 8개 필름·방향 조합, 권한 복구, 과거 ANR의 재현 여부 등 개별 결과를 임의로 채우지 않았습니다. [실기기 체크리스트](../physical-device-test-checklist.md)는 확인한 환경과 세부 결과를 보강하고 이후 회귀 검증에 사용하는 기준입니다.

README와 필터·생명주기·회전 문서에는 개발자의 완료 사실을 반영했습니다. 문서에 사용한 이미지와 아래 에뮬레이터 결과는 원래 촬영 환경·버전을 유지합니다.

## 다음에 해결할 과제

1. **완료한 검증의 세부 기록 보강.** 기기 모델·Android·앱 버전과 실제 검사 항목을 남기고, 과거 에뮬레이터에서 관찰한 첫 실행 ANR이 해당 실기기에서 재현됐는지도 함께 기록합니다.
2. **기기·화면 범위 확대.** 다른 카메라·GPU의 기기, 작은 창·분할 화면·폴더블에서 촬영과 복귀 동작을 확인합니다.
3. **촬영 품질과 성능 측정.** 조명·장면·해상도를 달리해 필터 결과를 비교하고 저장 지연·최대 메모리를 측정합니다.
4. **배포 준비와 회귀 검증.** 스토어 정보·개인정보 고지·배포 국가를 확정하고, 이후 코드 변경 때 완료한 사용 흐름을 다시 검사합니다.

성능 수치와 사용자 지표는 아직 성과로 제시하지 않습니다. 측정이나 실제 운영 결과가 생기면 환경과 함께 갱신할 항목입니다. **(후속 계획)**

## 검증을 이어가는 방법

코드·문서 변경 뒤에는 그 범위에 맞춰 검증합니다. 빌드·정적 검사·단위 테스트와 에뮬레이터 테스트는 분리합니다.

```sh
./gradlew :app:testDebugUnitTest :app:lintRelease :app:assembleRelease :app:bundleRelease
```

실제 기기 점검은 [실기기 체크리스트](../physical-device-test-checklist.md)를 기준으로 앱 버전·Git 상태·환경·판정을 남깁니다. 에뮬레이터 점검은 별도의 [에뮬레이터 체크리스트](../emulator-test-checklist.md)를 사용하며, 이 저장소의 [작업 지침](../../AGENTS.md)에 따라 해당 작업에 대한 사용자의 명시적 허가 후 수행합니다.

새 기록을 추가할 때는 이전 결과를 덮어쓰지 않고 검사한 버전과 관찰 날짜를 함께 남깁니다. 문서 이미지를 바꾸는 경우에도 원본 촬영 자료와 대응 관계를 유지합니다.
