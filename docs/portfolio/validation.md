## 검증 기준

필름 카메라는 앱이 켜지는 것만으로 검증이 끝나지 않습니다. 프리뷰에서 보인 선택이 JPEG에 반영되는지, 방향이 맞는지, 화면에서 돌아온 뒤 새 프레임과 촬영을 처리하는지까지 확인해야 합니다.

| 확인 대상 | 근거 | 이 근거만으로 판단하지 않는 것 |
| --- | --- | --- |
| 빌드·정적 검사 | Debug/Release 빌드, Lint, Manifest | 실제 첫 실행·촬영 성공 |
| 순수 상태 로직 | 권한 복구·촬영 허용 조건 등의 단위 테스트 | 시스템 권한 대화상자의 실제 동작 |
| GL·Surface | 실제 EGL/OES/SurfaceRequest를 사용하는 기기 테스트 | 모든 제조사·GPU의 자원 안정성 |
| 촬영 결과 | 촬영 직전 화면과 새 JPEG의 연결, 내용·크기 확인 | 기준 색상표 없는 절대 색 정확도 |
| 복귀·레이아웃 | 화면과 로그, 복귀 뒤 촬영 | 고정 그림만으로 움직이는 프리뷰 재개 |

근거를 확보하지 못한 항목은 미검증으로 남깁니다. EXIF 값만으로 사진 방향을 판정하지 않고 실제 픽셀 내용과 가로·세로 크기도 확인합니다. 검사 기준: [실기기](../physical-device-test-checklist.md) · [에뮬레이터](../emulator-test-checklist.md)

## 이전 버전의 앱 동작 점검

앱 1.0.1 (2)에서 확보한 촬영·회전·설정 자료입니다. 아래 관찰은 해당 버전에 한정하며, 현재 버전의 전체 기능 검증 결과를 뜻하지 않습니다.

| 검사 환경 | 값 |
| --- | --- |
| 앱 | 1.0.1 · versionCode 2 · Debug APK |
| 소스 기준 | HEAD `4ff6c0c` + 당시 커밋되지 않은 배포 전 수정 사항 |
| 기본 환경 | Android API 36 · arm64 · 1080×2400 · 420 dpi · SwiftShader |
| 카메라 입력 | 에뮬레이터의 고정된 가상 그림 |
| 추가 조건 | 기존 촬영 한도 24/24 데이터를 유지한 업데이트 검사 |
| APK SHA-256 | `9400497ccfb9b723f8c15b4007c49338f208359c4428c279677e316f1e66787b` |

아래 결과는 1.0.1 (2)에 한정하며, 이후 버전의 검증 결과로 옮기지 않았습니다. 현재 버전은 [빌드 설정](../../app/build.gradle.kts)에서 확인할 수 있습니다. 원본 실행 식별자는 `2026-10-08-release-fixes`이며, 로컬 `build/reports/newfeel-emulator-check/` 아래의 보고서를 바탕으로 공개용 요약을 작성했습니다. 원본 보고서·로그 폴더는 Git 추적 대상이 아니므로 이 페이지와 [선별한 이미지](../assets/app/README.md)에 필요한 내용을 보존했습니다.

WARM·DUSK와 네 방향의 조합에서 총 8개 JPEG를 저장했습니다. 세로 사진은 1392×1856, 가로 사진은 1856×1392였고, 픽셀에 반영된 장면 방향을 확인했습니다. DUSK로 촬영을 시작한 뒤 WARM으로 바꿔도 해당 JPEG와 로그에는 DUSK가 유지됐습니다.

시작 필름·격자 설정의 화면 왕복·프로세스 재시작 후 유지와, 이전 24/24 데이터를 보존한 업데이트 뒤 화면·볼륨 셔터로 추가 저장되는 것을 확인했습니다. 고정된 가상 그림을 입력으로 사용했으므로 움직이는 프리뷰의 연속 갱신은 이 자료로 판단할 수 없습니다. 저장 안내의 표시, 설정 화면의 시스템 음량 변경, 실패 후 재시도와 분할 화면 동작도 이 점검의 확인 범위에 포함하지 않습니다.

원본 보고서는 줌·플래시·갤러리를 검사 대상에서 제외했습니다. 현재 코드에는 해당 동작의 연결이 있으므로 이를 “미구현”으로 옮기지 않고, **이 점검에서 확인하지 않은 기능**으로 기록합니다.

## 다음에 해결할 과제

1. **기기·화면 범위 확대.** 다른 카메라·GPU의 기기, 작은 창·분할 화면·폴더블에서 촬영과 복귀 동작을 확인합니다.
2. **촬영 품질과 성능 측정.** 선택한 JPEG 품질 95에서 장면별 용량·세부 표현과 해상도별 저장 지연·최대 메모리를 측정합니다. 질감 손실이나 용량·지연 문제가 관찰되면 품질 값을 재검토합니다. [JPEG 품질 선택 근거와 재검토 기준](filter-pipeline.md#jpeg-품질과-파일-용량)
3. **배포 준비와 회귀 검증.** 스토어 정보·개인정보 고지·배포 국가를 확정하고, 이후 코드 변경 때 완료한 사용 흐름을 다시 검사합니다.

성능 수치와 사용자 지표는 아직 성과로 제시하지 않습니다. 측정이나 실제 운영 결과가 생기면 환경과 함께 갱신할 항목입니다. **(후속 계획)**

## 검증을 이어가는 방법

코드·문서 변경 뒤에는 그 범위에 맞춰 검증합니다. 빌드·정적 검사·단위 테스트와 에뮬레이터 테스트는 분리합니다.

```sh
# Firebase 설정 파일 없이도 실행할 수 있는 기본 검사
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug

# app/google-services.json이 있는 환경의 Release 빌드 검사
# 이 명령은 Crashlytics 매핑 파일 업로드를 제외합니다.
./gradlew :app:lintRelease :app:bundleRelease -x :app:uploadCrashlyticsMappingFileRelease
```

실제 기기 점검은 [실기기 체크리스트](../physical-device-test-checklist.md)를 기준으로 진행합니다. 에뮬레이터 점검은 별도의 [에뮬레이터 체크리스트](../emulator-test-checklist.md)를 사용하며, 이 저장소의 [작업 지침](../../AGENTS.md)에 따라 해당 작업에 대한 사용자의 명시적 허가 후 수행합니다.

자동 검증 기록과 실행 자료에는 검사한 코드·앱 버전을 표시합니다. 문서 이미지를 바꾸는 경우에도 원본 촬영 자료와 대응 관계를 유지합니다.
