## 시작한 이유

촬영 전에 색감을 고르고, 그 결과를 사진으로 남기는 카메라를 만들고 싶었습니다. 이를 위해 “사용자가 프리뷰에서 본 필름 효과와 저장된 사진의 효과가 시각적으로 최대한 일치해야 한다”는 기준을 먼저 세웠습니다. **(제품 요구사항)**

이 요구를 구현하려면 카메라 프레임이 화면에 도달하는 과정과 촬영 사진이 파일로 저장되는 과정을 함께 이해해야 했습니다. CameraX·Compose뿐 아니라 Surface, SurfaceTexture, OpenGL ES, 셰이더, Android 생명주기를 학습 범위에 포함한 이유입니다.

첫 구현 범위는 후면 카메라와 WARM·DUSK 두 필름, 촬영·저장·화면 복귀였습니다. 필터 종류를 늘리기 전에 한 장의 사진이 만들어지는 전체 흐름부터 연결했습니다. **(구현 순서에 대한 결정)**

## 담당 범위와 작업 방식

| 범위 | 프로젝트에서 다룬 내용 |
| --- | --- |
| 제품 기획 | 필름 선택과 촬영 경험, 초기 기능 범위, 무료 출시 정책 |
| UI와 상태 | Compose 카메라·설정 화면, 셔터 입력, 설정 영속화, 방향별 표시 |
| 카메라·렌더링 연동 | CameraX UseCase, Surface 공급, OES 프리뷰, LUT 업로드와 적용 |
| 사진 처리 | 촬영 시점 상태 고정, offscreen GL 처리, JPEG·MediaStore 저장 |
| 품질 확인 | 자원 소유권 검토, 자동 테스트, 직접 실기기 확인, 화면·사진·로그 기반 점검 기록 |

초기 협업 원칙은 AI에 요구사항 정리, 설계 비교, 코드 골격, 구현 순서 제안과 리뷰를 맡기고, 핵심 CameraX·GL 흐름을 직접 구현하며 학습하는 것이었습니다. 기능을 빨리 추가하는 것과 원리를 이해하는 것 사이에서 학습할 경계를 먼저 정했습니다.

코드를 한 단계씩 작성하며 모든 개념을 익히는 방식은 예상보다 진행이 느렸습니다. AI의 구현 능력이 발전하면서, 먼저 동작하는 코드를 함께 만든 뒤 실행 흐름을 따라가며 모르는 부분을 찾아 공부하는 방식으로 바꿨습니다. 구현을 진행하면서 학습하고, 제안마다 다른 방법이 있는지 비교하며 수정과 적용 여부를 AI와 함께 판단했습니다. 촬영 분석 이벤트와 반복 오류 알림 개선은 AI가 코드·테스트 작성까지 맡은 사례입니다. [학습 방식의 변화와 실제 협업 사례](ai-collaboration.md)

WARM·DUSK LUT와 초기 셰이더는 제공된 자산을 사용했습니다. 필름의 원본 색보정 자산을 자체 제작했다고 주장하지 않으며, 이 문서에서는 자산 형식 확인, GPU 업로드, 프리뷰·촬영 연결, 자원 수명과 결과 검증을 다룹니다. [자산 구조](../../new_feelcamera_filter_assets/README.md)

의사결정은 다음 세 가지로 구분해 기록했습니다.

- **지금 확정:** 같은 필름 모델과 LUT 사용처럼 이후 구현 전체에 영향을 주는 조건.
- **관찰 후 판단:** Surface 교체, 화면 재생성, 저장 색감처럼 실제 코드와 기기에서 확인할 조건.
- **후속 검토:** 추가 효과, 폴더블 자세별 UI, 유료화처럼 현재 촬영 흐름 이후의 기능.

## 초기 출시 범위를 바꾼 이유

처음에는 24장 무료 촬영 후 일회성 구매로 제한을 해제하는 방식을 준비했습니다. 첫 출시에서는 **완성한 앱을 배포하고 운영하는 경험**을 우선했습니다. 초기 사용자 수와 매출이 불확실한 상황에서 **유료 판매에 필요한 세무 검토와 결제 운영 부담**이 무료 출시로 바꾼 주요 계기였습니다. 판매 국가·세금 처리와 구매 확인·복원·환불 대응을 첫 버전의 운영 범위에 포함할지 다시 검토했습니다. **(2026-10-08 제품 결정)**

이에 첫 버전의 유료화를 보류하고, 촬영 품질을 다듬고 제품을 배포해 피드백을 받는 데 집중하기로 했습니다.

| 선택지 | 얻는 것 | 감수할 점 |
| --- | --- | --- |
| 촬영 한도와 일회성 구매 | 유료 판매 시도, 준비한 Billing 구현 활용 | 판매 국가·세금 처리 검토, 구매 확인·복원·환불 대응 |
| 무료·무제한 촬영 | 유료 판매 준비를 미루고 촬영 품질과 배포·피드백에 집중 | 첫 버전의 수익화 보류, 이후 유료화 시 판매·결제와 기존 무료 사용자 정책 재검토 |

최종적으로 첫 버전은 **무료 다운로드, 촬영 횟수 제한 없음, 광고 없음, 인앱결제 없음**으로 정했습니다. 일회성 구매를 보류하면서 촬영 한도도 함께 제거했습니다.

구현에서도 구매 안내만 숨기는 것으로 끝내지 않았습니다. 화면·볼륨 셔터가 이전 무료 촬영 카운터와 무관하게 동작하도록 바꾸고, 결제·한도 코드를 별도 소스 디렉터리에 보존해 기본 빌드에서 제외했습니다. 이전 24장 한도에 도달한 데이터로 업데이트한 뒤에도 촬영되는지는 별도 점검 항목으로 삼았습니다. [기존 데이터에서의 확인 결과](validation.md#이전-버전의-앱-동작-점검)

2026-10-09에는 무료 출시와 운영 모니터링을 함께 제외했던 정책을 수정했습니다. Release AAB에 Firebase Analytics·Crashlytics를 기본 포함하고 첫 실행과 설정에서 수집 여부를 선택하도록 연결했습니다. 동의한 사용자의 촬영 이벤트와 오류 보고로 사용 상황을 파악하며, 콘솔 수신 검증은 빌드 검증과 별도로 진행합니다. [Firebase 설계와 현재 정책](../features/firebase-monitoring.md)

## 이후의 방향

Galaxy S10(Android 12)과 Galaxy S25+(Android 16)에서 직접 실기기 검증을 진행했습니다. [검증 범위](validation.md#실기기-검증-완료)

이후에는 기기별 검증 범위를 넓히고 촬영 해상도별 저장 지연과 메모리를 측정하며, 작은 창과 큰 화면에서의 배치를 다듬을 계획입니다. **(후속 검증 계획)**

추가 필름이나 유료화는 사용자 요구와 운영 여력을 확인한 뒤 검토합니다. 기존 무료 사용자에게 제공할 경험도 그때 다시 정하며, 과거의 24장 제한을 그대로 복원하는 것을 전제로 하지 않습니다.
